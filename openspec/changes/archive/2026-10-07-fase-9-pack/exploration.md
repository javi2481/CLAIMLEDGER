### Approaches

1. **Subtract outside the kernel, in a sibling package, from the two claims `query` already verified** — A new package next to `card/`, `eval/`, `crop/`, and `http/` (for example `src/claimledger/period/`) exposes one function that takes the `QueryResult` and returns either a signed canonical digit string or nothing. It returns a number only when `status == "verified"`, there are exactly two claims, issuer, statement, scope, metric, currency, and unit all match, the two periods differ, and both claims are `recorded`. Order is later period minus earlier period, so `2026-06-30` minus `2026-03-31`. The result is a string in `signed_ars` shape. It is not a `FinancialClaim`, it gets no `identity_key`, and it is never upserted. `query`, `QueryResult`, `Ledger.seed()`, `lookup`, `digits`, the graph package, ingest, and `POST /claims/query` are untouched. `render_card` may place that string beside the two values it already shows, without computing it. `card_text` keeps the card order and the host keeps one completion with the card text first and the crop after. Spec deltas are narrow: `claim-card` and `openwebui-host` stop saying subtraction must wait; `query` and `verify-eval` say the subtraction lives outside `query` and that `query` still returns two claims with no delta field. Gold stays exactly as it is: `cp-*` still expect two values and the harness still asserts no difference. Tests are in-memory on `Ledger.seed()`: no docling import, no network, no PDF, no Docker.
   - Pros: matches §20 literally — the two claims stay side by side and code computes the difference. The kernel judge is untouched, so the 13-path allowlist, `test_query_result_is_frozen_dataclass`, and the frozen compare gold all stay green without being relaxed. The gap is the one the 2026-10-06 audit already named, so no library is re-copied and no pin is added. Same sibling-package shape the repo has used four times. Rollback is deleting one package and reverting two display sentences.
   - Cons: a second module now knows the compare shape (two claims, same scope and metric, different periods), so a future change to compare has to touch two places. Needs four narrow spec deltas instead of one. If the difference is shown on screen, the compare card grows a line, which brushes against `_METRIC_CHIP` covering only `net_income`.
   - Effort: Medium

2. **Add a `delta` field to `QueryResult` and subtract inside `query`** — The judge returns the two claims plus the computed difference.
   - Pros: one call site; the difference arrives with the claims it came from.
   - Cons: breaks `tests/test_query.py::test_query_result_is_frozen_dataclass`, a kernel test on the 13-path allowlist that asserts `delta` and `difference` are not fields; breaks the `query` spec return shape; breaks `http-query`'s "MUST NOT include `delta` or a subtracted number"; and collides with the gold compare partition, where `cp-*` expect two values and "no subtracted difference MUST be asserted". §20 says code computes the difference, not that the verdict carries it. Verification and arithmetic are two jobs.
   - Effort: Medium — **reject**

3. **Write a second pack merger in `ingest/` or `graph/`** — A new function that collects the same-period documents and folds them.
   - Pros: "pack" would have a module with that name.
   - Cons: `fold_documents` plus `GraphConverter(alias_llm_fn=None)` plus `GraphMerger(policy=MergePolicy(conflicts="keep-all"))` already do it, `document-graph` already specs it, and `tests/graph/test_fold.py::test_same_period_pack_shares_issuer_period_statement_and_hash` already proves it. The 2026-10-06 audit lists all of those as `keep` direct calls. Writing it again is re-copying the library and re-copying our own archived phase.
   - Effort: Medium — **reject**

4. **Let Open WebUI, an LLM, LlamaIndex, or a code-interpreter artifact compute the difference** — The screen or a model does the arithmetic.
   - Pros: no new module.
   - Cons: principle 9 says Open WebUI draws and does not calculate; principle 18 says no agent skips the kernel; §20 says code computes the difference. Pipelines and Knowledge RAG stay out, the orchestrator is phase 13, and charts are phase 12. A model that subtracts can also mistype a digit the kernel just verified.
   - Effort: Low — **reject**

5. **Mint the difference as a `FinancialClaim` and upsert it** — A third claim, maybe keyed on a synthetic period.
   - Pros: the difference would flow through the existing card and route with no new surface.
   - Cons: the five-field identity has no period for a difference; principles 19 and 20 say the claim appears when the contract is met and the question does not create the claim; no document states `60694190`, so sealing it `VERIFICADO` claims a document said something it did not; `Ledger.seed()` is the gold book and must stay the 14 frozen `RECIPE_ROWS`.
   - Effort: Medium — **reject**

6. **Put the difference on `POST /claims/query`** — Add `delta` to the compare body.
   - Pros: one JSON would carry both claims and their difference.
   - Cons: `http-query` is an archived contract that explicitly forbids `delta` and a subtracted number in the compare requirement, and the route's job is `understand` then `query` with `query` as the judge. The screen already has the card. If that body ever needs the difference, it is its own gated delta, not a side effect of phase 9.
   - Effort: Medium — **reject**

7. **Subtract inside `render_card` or `card_text`** — The display layer does the arithmetic on the value strings.
   - Pros: no new package at all.
   - Cons: `claim-card` says the card is pure display, MUST NOT call the kernel, and MUST NOT parse digits. Turning `"81956525"` into an integer is parsing digits. The card may show a number another module computed; it must not be the module that computes it.
   - Effort: Low — **reject**

### Recommendation

Take approach **1**. The user opened the phase 9 gate, and the honest reading of the gate question is split: "¿Hace falta más de un documento?" is already answered yes and already built — `fold_documents` plus `GraphMerger(conflicts="keep-all")` merge the same-period EEFF, comunicado, and deck with the clash visible, `Ledger.upsert` folds evidence for one identity across documents, and `extract_recipe` keeps comunicado and deck out of the recipe. "¿Restar en código?" is the part nothing does. That is the single gap this change closes, and the 2026-10-06 audit already named it: no pinned API subtracts two verified claims.

The subtraction goes in a sibling package outside the seven kernel modules, takes the `QueryResult` `query` already produced, and returns a signed canonical digit string only when the two claims share issuer, statement, scope, metric, currency, and unit, differ in period, and are both `recorded`. Later period minus earlier period. It is not a claim, it has no identity, it is never upserted, and it is never read by the gold harness. `query` still returns two claims and `QueryResult` still has no `delta` and no `difference` field, so `tests/test_query.py`, the 13-path allowlist, and the frozen `cp-*` expectations stay untouched. If the difference reaches the screen, `render_card` shows what that function computed, `card_text` keeps the card order, and the host keeps one completion with the card text first and the crop after.

**In this change:** the code-side subtraction of two verified compare claims; the guard rails that make it refuse anything other than one metric across two periods; narrow spec deltas on `claim-card` and `openwebui-host` to stop saying subtraction waits, plus a sentence in `query` and `verify-eval` that names where the subtraction lives while keeping `query` free of a delta; a written statement that the period pack is already satisfied by fase-1a corpus parse, the fase-2 graph merge, and `Ledger.upsert`; and in-memory tests on `Ledger.seed()`.

**Waits:** phase 10 VLM, phase 11 Neo4j, phase 12 charts, phase 13 orchestrator. Also still out: MinerU, Markdown as retrieval source of truth, LLM-written `identity_v1`/`identity_v2`, an agent that skips the kernel, relaxing gold numbers, Pipelines, Knowledge RAG, a `delta` field on `QueryResult`, a `delta` field on `POST /claims/query`, a second pack merger, and a 15th row in `RECIPE_ROWS`.

### Risks

- **Gold forbids the delta the phase asks for.** `gold-regression` says comparison cases MUST return two verified claims and that for any `cp-*` "no subtracted difference MUST be asserted", and `cp-03` is the "Diferencia…" question with `expected_values` as the pair. The subtraction must stay off the gold harness. Pointing `tests/test_gold_v1.py` at a difference, or editing `expected_values`, is relaxing gold.
- **Kernel test and allowlist.** `tests/test_query.py::test_query_result_is_frozen_dataclass` asserts no `delta` and no `difference` field, and `test_graph_init_outside_kernel_allowlist` asserts the allowlist is exactly 13 paths. Phase-9 code and its tests stay off that list, and `QueryResult` keeps its four fields.
- **The difference is not a claim.** No BYMA document prints `60694190`. Sealing it `VERIFICADO`, giving it an `identity_key`, or upserting it would make the ledger assert something no evidence supports. It is arithmetic on two claims, presented as such.
- **Cumulative versus standalone quarter.** The 2T26 EEFF `net_income` is the figure that document reports for its period; it is not guaranteed to be the stand-alone second quarter. The computed number is the difference between those two verified claims and must be labelled that way. Calling it "the second quarter alone", or deriving a new quarterly figure from it, invents accounting the kernel did not verify.
- **Sign, order, and string shape.** Values are strings, including `-14950948`, and `digits.py` has no arithmetic. Reversing the period order flips the sign; dropping the sign on a negative metric produces a wrong number silently. Order must be later minus earlier, and the output must stay in the `signed_ars` shape.
- **Mismatched pairs.** A pair that differs in scope, metric, currency, or unit, or two claims for the same period, must yield no number rather than a meaningless one. `conflicted` claims never reach `query`, but the function must still refuse anything that is not `recorded`.
- **Chip vocabulary.** `_METRIC_CHIP` maps only `net_income` and `_label` raises on an unknown token, so a compare card for `gross_profit` already fails today. Phase 9 must not widen that vocabulary as a side effect; if the card line needs it, that is a named decision, not a quiet edit.
- **Archived display wording.** `openwebui-host` currently says subtraction must wait and phases 9–13 must not start, and `claim-card` says a compare card must not subtract or show a delta. Shipping a visible difference without those deltas contradicts the archive; the deltas must retire only those sentences.
- **Route creep.** Adding `delta` to `POST /claims/query`, or a second product route, breaks `http-query` and the "one product route" rule.
- **Kernel bans.** No `docling` import in kernel tests, no network, no PDF, no Docker. The subtraction has no reason to touch any of them; its tests run on `Ledger.seed()` in memory.
- **400-line review budget.** Subtraction plus guard rails, a card line, a host line, and four spec deltas can approach the budget. `sdd-tasks` still forecasts it and should consider slicing the kernel-free subtraction from the display.
